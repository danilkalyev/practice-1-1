# Задание 1. Разбор tsconfig.json

Откройте `tsconfig.json` в корне проекта и для каждой строки напишите
**своими словами**, что она делает. Не копируйте документацию —
объясните так, как будто рассказываете одногруппнику.

## compilerOptions

### target
> Версия JavaScript, в которую TypeScript превращает наш код.
> Здесь ES2020, значит современный синтаксис можно писать спокойно.

### module
> Формат модулей в готовом коде. ESNext — остаются обычные `import` и `export`.

### moduleResolution
> Правила, по которым компилятор ищет файл из `import`.
> Режим `bundler` разрешает писать путь без расширения `.ts`.

### strict
> Один переключатель, который сразу включает пачку строгих проверок.
> Сейчас он выключен, поэтому нужные проверки включаем по отдельности.

### strictNullChecks
> Не даёт считать `null` и `undefined` подходящими для любого типа.
> Из-за неё компилятор требует сначала проверить значение, а потом использовать.

### esModuleInterop
> Позволяет подключать старые CommonJS-библиотеки обычным `import`.

### skipLibCheck
> Не проверяет типы внутри библиотек из `node_modules`, поэтому проверка идёт быстрее.

### forceConsistentCasingInFileNames
> Требует писать имя файла в импорте ровно тем же регистром, что и на диске.
> Windows разницы не видит, а Linux видит — так ошибка найдётся сразу.

### outDir
> Папка `dist`, куда попадут скомпилированные JavaScript-файлы при сборке.

### rootDir
> Корень исходников, относительно него строится структура папок внутри `dist`.

## include
> Какие файлы вообще входят в проект: всё из `src` и `tests`.

## exclude
> Какие файлы из проекта убрать: `node_modules` и `dist`.

# Задание 1.2. Включение флагов

Для каждого пункта ниже:
1. Определите, какой флаг нужно поменять в `tsconfig.json`.
2. Внесите изменение.
3. Запустите `npm run check`.
4. Запишите результат в `task1.md`.

---

### 1. Строгие проверки типов
Включите опцию, которая делает `null` и `undefined` отдельными типами,
а не «совместимыми со всем». Без неё код с `null` компилируется, с ней — нет.

**Ваш ответ:** `strictNullChecks`

---

### 2. Проверка `this`
Включите опцию, которая ругается, если внутри функции используется `this`,
но функция не является методом класса (то есть `this` не определён).

**Ваш ответ:** `noImplicitThis`

---

### 3. Неявный `any`
Включите опцию, которая ругается, если переменная получает тип `any`
автоматически (например, функция без аннотаций параметров).

**Ваш ответ:** `noImplicitAny`

---

### 4. Возврат из функции
Включите опцию, которая требует, чтобы **все** ветки функции возвращали значение,
если функция объявлена как возвращающая не-`void`.

**Ваш ответ:** `noImplicitReturns`

---
